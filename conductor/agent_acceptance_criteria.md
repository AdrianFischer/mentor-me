# Acceptance Criteria: Node.js Intelligent Agent

This document defines the 50 specific criteria that the standalone Node.js Intelligent Agent must meet to be considered complete and operational. These criteria are used for communication across agents and for final verification.

## 1. Project Infrastructure
1.  [x] Agent project exists in a dedicated `agent/` directory in the repository root.
2.  [x] `package.json` includes required dependencies: `telegraf`, `@google/generative-ai`, `@modelcontextprotocol/sdk`, and `dotenv`.
3.  [x] Agent uses ES Modules (`"type": "module"`) for modern JavaScript support.
4.  [x] A `README.md` exists in the `agent/` folder with setup and debug instructions.
5.  [x] `npm install` runs successfully without dependency conflicts.
6.  [x] The agent code is linted and free of syntax errors.

## 2. Configuration & Secrets
7.  [x] Agent loads `TELEGRAM_BOT_TOKEN` from the `app/.env` file.
8.  [x] Agent loads `GEMINI_API_KEY` from the `app/.env` file.
9.  [x] Agent correctly reads the MCP server port from `~/.assisted_intelligence/mcp_port`.
10. [x] The agent fails gracefully with a clear error if `.env` or port file is missing.
11. [x] Secrets (Tokens/Keys) are never printed to the console or log files.

## 3. Telegram Integration
12. [x] Bot initializes and connects to the Telegram Bot API successfully.
13. [x] Bot responds to the `/start` command with a welcome message and feature overview.
14. [x] Bot supports receiving and processing standard text messages.
15. [x] Bot acknowledges receipt of voice memos (even if transcription is not yet implemented).
16. [x] Bot uses `parse_mode: 'Markdown'` with an automatic fallback to plain text if parsing fails.
17. [x] Bot provides a `/model` command to switch between AI models using inline buttons.
18. [x] Bot provides `/start_day` and `/end_day` commands to trigger context-aware workflows.
19. [x] Bot maintains a stable connection and automatically reconnects on network drops.

## 4. Gemini AI Integration
20. [x] Agent supports switching between "Fast" (Gemini 2.0 Flash) and "Smart" (Gemini 3.1 Pro Preview) models.
21. [x] System prompt defines the AI's persona as "Assisted Intelligence Agent".
22. [x] Gemini is configured to use Function Calling (Tools) to interact with the app.
23. [x] Gemini receives the full list of available tools from the MCP connection.
24. [x] Gemini can generate a natural language response after a tool execution.
25. [x] Agent maintains a sliding window of chat history (last 20 messages) for context.
26. [x] Agent handles Gemini API errors (rate limits, safety filters) without crashing.

## 5. MCP Client Functionality
27. [x] Agent successfully connects to the Flutter app's SSE transport.
28. [x] Agent performs "Tool Discovery" immediately upon connection.
29. [x] Agent can call the `list_todos_by_status` tool and parse the JSON output.
30. [x] Agent can call `update_todo_by_index` with parameters generated by Gemini.
31. [x] Agent can call `save_memory` to persist facts to the local database.
32. [x] Agent can call `manage_todo_images` to add/remove artifact paths.
33. [x] Agent handles timeouts and connection failures gracefully with retries.
34. [x] Agent detects if the Flutter app is closed and notifies the user via Telegram.

## 6. Functional Workflows (Conversational)
35. [x] User says "What tasks do I have?": AI calls `list_todos_by_status` and displays them.
36. [x] User says "Mark task 2 as done": AI calls `update_todo_by_index` and confirms.
37. [x] User says "Add notes to task 1": AI prompts for notes or updates them directly.
38. [x] User says "Remember I am allergic to peanuts": AI calls `save_memory` and confirms.
39. [x] AI correctly maps user-facing indices (1, 2, 3) to internal UUIDs via the MCP bridge.
40. [x] AI can handle complex requests like "Show my finished tasks from the last project".
41. [x] AI proactively asks for clarification if a tool call requires more parameters.

## 7. Logging & Debugging
42. [x] Agent prints a clear timestamped log for every incoming Telegram message via `logger.js`.
43. [x] Agent logs every tool call sent to the Flutter app.
44. [x] Agent logs the raw response from every tool execution.
45. [x] Logs are persisted to `agent/logs/agent.log` for future analysis.

## 8. Performance & Reliability
46. [x] Average response time for a text message (including tool call) is under 5 seconds.
47. [x] Agent memory usage remains stable (no memory leaks in the event stream).
48. [x] Parallel requests from the same user are handled sequentially or safely.

## 9. System Integration
49. [x] The `StartAssistedIntelligence.app` macOS button is updated to launch the Node.js agent and app concurrently.
50. [x] The architecture successfully separates "Brain" (Node.js) from "View" (Flutter).
